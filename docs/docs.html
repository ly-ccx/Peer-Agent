Get started / Welcome

Welcome to Peer Agent

Local hands for your AI. Peer Agent is a privacy-first desktop and CLI agent platform: every capability is authorized, executed on your machine, and left as Evidence you can audit.

Core idea

Peer Agent follows one chain: Capability Provider → Manifest → Runtime Projection → Tool Call → PermissionGrant → Evidence. The cloud can reason; local owns capability.

Desktop

A governable workbench for Thread, Workbench, and visual Evidence.

CLI · peer

First-class terminal entry. No Desktop required. Same local Runtime.

Principles

  • Local-first — keys, files, and execution stay on your machine.
  • Permission-gated — capabilities run only after explicit grants.
  • Evidence-backed — tool results return structured artifacts you can inspect.

Quick start

  1. Install Desktop from Releases, or install CLI with npm install -g @peer-agent/cli.
  2. Open Peer Agent and configure a model provider.
  3. Start a task. Approve capabilities when asked. Review Evidence after runs.

Get started/ Install

Install

Choose Desktop for a visual workbench, or CLI for terminal / headless use. Both share ~/.peer-agent.

Download the latest macOS or Windows build from GitHub Releases and install like a normal app.

pnpm install
pnpm --filter @peer-agent/desktop dev
Get started/ Desktop

Desktop workbench

Desktop is the visual shell: Executive Thread in the center, workspace sidebar on the left, Workbench and Evidence when you need deeper inspection.

Layout

  • Sidebar — workspace, new task, conversation list.
  • Thread — decision and execution stream, not an IM wall.
  • Composer — mode, access, model chips; send tasks from here.
  • Evidence — expandable tool traces and artifacts after actions.

First run

  1. Open Peer Agent and pick or create a workspace.
  2. Configure a model in Settings if none is available.
  3. Start with a small local task (read a file, summarize git status).
  4. When a permission prompt appears, grant only what you need.
Get started/ CLI

CLI · peer

peer is a first-class TUI entry. It uses the same local Runtime, settings, conversations, and credentials as Desktop under ~/.peer-agent.

Start

peer
peer --version

Status bar

The TUI status row typically surfaces mode, access policy, model, effort, and context usage — so terminal sessions stay as governable as the GUI.

Slash commands

Type / in the composer for commands (model, mode, MCP, goals, and more as they ship). Use Tab for completion where available.

Shared Runtime: start in terminal, continue later in Desktop — same local state.
Get started/ Connect a model

Connect a model

Peer Agent is model-provider flexible. Configure credentials locally; keys stay in your machine-side storage path.

In Desktop

  1. Open Settings → Models / Providers.
  2. Add a provider and paste the API key or local endpoint.
  3. Select a default model for new threads.

In CLI

Use the TUI model command / settings path once installed. Configuration is shared with Desktop via ~/.peer-agent.

Concepts/ Local Runtime

Local Runtime

The local Runtime is the product spine. Shells (Desktop / CLI) are presentations; capability truth lives locally.

Capability chain

Capability Provider
  → Manifest
    → Runtime Projection
      → Tool Call
        → PermissionGrant
          → Evidence

Data home

Shared local state lives under ~/.peer-agent — settings, conversations, credentials, and runtime artifacts.

Concepts/ Permissions

Permissions

Peer Agent does not treat prompt text as authorization. Capabilities need PermissionGrant before local execution.

Ask first

Default posture is cautious: sensitive tools (filesystem writes, shell, network-ish actions) should surface a clear approval path.

Scope

Prefer workspace-scoped access over machine-wide access. Grant the smallest capability that completes the task.

Concepts/ Evidence

Evidence

Evidence is the audit surface. When the agent reads a file, runs a command, or calls a tool, you should be able to expand what happened — not just trust a chat summary.

What you get

  • Tool identity and authorization state
  • Structured result metadata
  • Artifact references for larger outputs

Why it matters

Local agents are powerful. Evidence keeps model intent, local execution, and user authorization separate and reviewable.

Capabilities/ Overview

Capabilities overview

Capabilities are declared, projected to the model as tools, then executed only after grants.

Area Examples
Files Read, search, edit workspace files
Shell Run local commands under policy
MCP Install and call MCP servers from local registry
App automation Desktop-side automation paths as they ship
Capabilities/ MCP

MCP servers

Peer Agent can load MCP servers from a local registry. Disabled servers stay installed but not projected as tools until enabled.

Typical flow

  1. Install or register an MCP server locally.
  2. Enable it in the registry / settings UI or CLI path.
  3. Re-sync tools so the model can call them under permission rules.
Help/ FAQ

FAQ

Does Peer Agent upload my files to the cloud?

Capability execution is local. Model providers only receive what the agent deliberately sends in prompts/tool payloads — review permissions and Evidence.

Do CLI and Desktop share history?

Yes. Both use the same local Runtime home under ~/.peer-agent.

Is Windows supported?

Desktop targets macOS and Windows builds via Releases. CLI multi-arch coverage expands as binaries ship on the same release tags.

Where do I report issues?

Use GitHub Issues on the Peer-Agent repository.
