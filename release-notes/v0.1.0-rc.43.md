## 说明

- 本版本修复在 Bot 设置中切换模型（特别是 Google AI / Gemini 及含 `default` 推理档位的模型）时保存失败并被锁死的问题，并完善自定义推理档位映射与保存失败原因提示。

## 修复

- **修复 Bot 设置中切换模型保存失败（`INVALID_REASONING_EFFORT`）**：补齐 Rust RPC `project.profile.update` 校验白名单中缺失的 `"default"` 推理档位，与 TypeScript 协议 7 档（`off` / `low` / `medium` / `default` / `high` / `xhigh` / `max`）保持一致，解决选择 Google AI / Gemini、Kimi、Anthropic、GPT-5.4 等含 `default` 档位模型时无法保存的问题。
- **对齐默认推理档位与自定义 `reasoningEffortMap`**：`modelDefaultReasoningEffort()` 现已识别后端透传的 `reasoningDefaultEffort`；`modelReasoningLevels()` 与渠道解析层现已支持从模型设置中自定义的 `reasoningEffortMap` 推导合法推理档位。
- **防止未改动的旧角色配置锁死整个 Bot 模型保存**：修改单个角色（如「对话模型」）时，未改动的其他角色或范围中的历史停用/过期模型引用不再阻断当前保存。
- **透出模型保存失败具体原因**：Bot 模型选择反馈条不再吞掉错误码，保存失败时会附带具体原因（如档位不支持、快速模式不支持或错误码），方便定位问题。

## Notes

- This release fixes Bot Settings model switching failures (especially for Google AI / Gemini and models whose reasoning levels include `default`), syncs custom reasoning effort maps into selectable levels, and surfaces concrete save error details.

## Fixes

- **Fix Bot Settings model switch rejection (`INVALID_REASONING_EFFORT`)**: Added the missing `"default"` reasoning effort level to the Rust `project.profile.update` RPC validator so it matches all 7 TypeScript protocol levels (`off`, `low`, `medium`, `default`, `high`, `xhigh`, `max`), resolving save failures when selecting Google AI / Gemini, Kimi, Anthropic, GPT-5.4, and other models using `default`.
- **Align default effort & custom `reasoningEffortMap` levels**: `modelDefaultReasoningEffort()` now respects `reasoningDefaultEffort` emitted by the config store, and `modelReasoningLevels()` / channel resolution derive selectable effort levels from custom `reasoningEffortMap` entries on non-fixed-contract channels.
- **Prevent untouched stale role overrides from blocking saves**: Updating one Bot role model no longer fails due to untouched historical overrides or scope entries referencing disabled/removed models or outdated effort levels.
- **Surface specific save failure reasons**: `BotModelFeedback` now displays the underlying save failure reason (e.g., unsupported reasoning effort, unsupported fast mode, or error code) instead of hiding it behind a generic failure banner.
