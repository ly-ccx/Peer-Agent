## 发布说明

- **0.1.0-rc.26** 基于 RC25，合入发布前全部开放 PR，改善机器人回复的连贯性、任务核验收尾与桌面界面。正式版仍为 0.0.18。

## 修复与优化

- 等待、流式内容与正式答复沿用同一条回复，头像、公开段落和详情入口自然衔接；发送回执不再被误当成答复完成。
- 每条输入等待自己的答复；调度让出、断线恢复、停止和重试保留原交互位置与历史，重开时不凭空显示任务正在执行，也不自动重发未知结果的操作。
- 侧栏与对话头像共享当前回复状态，回复时活动、待机时闭眼休息；进行中的状态使用轻量扫光，并尊重减少动态效果设置。
- 内部核验结论和核验进度进入对应任务详情，主 Bot 在对话中说明用户关心的结果；旧记录与证据保留，内部 passed 等核验回执不再占据主对话。
- 对已经返回结果、长时间尚未完成验收的任务，沿用既有停滞事件提醒主 Bot 补完核验；真实待批和待答继续保留，不绕过验收门。
- 目标面板按统一生命周期表达技术阻塞与人工处理状态，避免持续显示“执行中”。
- 收紧单行状态和后台任务的间距，统一 macOS 整窗毛玻璃底色，移除侧栏分隔线；深浅主题使用中性底面及独立悬浮的主面板、详情面板及设置内容区，设置导航也不再绘制分隔线。外观设置可切换毛玻璃/实色，减少透明度时保留浮层布局。
- 启动动画改为独立全窗口布局，移除误继承聊天区内边距造成的双色白边；加载失败仍显示明确说明。
- 修复已激活日志的完整备份换位置后无法恢复的问题：用完整内容证明校验旧日志，保留原有标记、事件链与证据；大文件按有界块异步核对，正常读取不重复扫描。
- 修正本地打包命令，确保调用桌面安装包脚本。同步中英发布说明、使用文档和网站更新日志。

## 数据与验收边界

- 保留现有任务、对话、证据与其他未提交改动；主 Bot 默认读取公开用户交互，子链过程仍按需调查。
- RC25 旧备份若尚无内容证明，需要用仍可信的只读原件认证；原件不可用时保留数据并报告阻塞，不能仅凭时间和大小自动放行。RC26 会在原数据目录准备时补充证明，后续完整备份应一并携带。
- 本次只发布，不安装、不替换或重启当前应用。新版本在用户安排升级后生效。
- 发布前对最终组合源码执行全量回归、产品逐图自审，并使用候选安装包的实际模块在隔离数据副本验证恢复；自审不等于独立审查。
- 受控认知不代表所有云模型的质量和时延；Windows/Linux 原生交互安装、完整读屏和长期日用不在本轮验收范围内。

## Release notes

- **0.1.0-rc.26**, based on RC25, includes every outstanding pull request for this release and improves continuous Bot replies, verification follow-up and desktop presentation. Stable remains 0.0.18.

## Fixes and improvements

- Keep waiting, streamed content and the final answer in one reply, preserving the avatar, public paragraphs and details entry. A saved-input receipt does not count as an answer.
- Track each input's answer separately. Scheduling yields, connection recovery, stopping and retries preserve interaction placement and history. Reopening does not invent active execution or replay operations with unknown outcomes.
- Link sidebar and conversation avatars to the current reply: animate during replies and rest with closed eyes when idle. Active status shimmer respects reduced motion.
- Keep internal verification verdicts and progress in their task details while the main Bot explains the result to the user. Preserve historical records and evidence without showing internal passed receipts in the main conversation.
- Use the existing stall-event path to prompt verification of overdue, unaccepted results. Preserve real approval and question waits and all acceptance gates.
- Show lifecycle-based follow-up and human-action states in goal headers instead of leaving blocked work marked as executing.
- Tighten single-line status and background-work spacing. Unify the macOS glass backdrop and remove the sidebar divider. Light and dark themes use neutral surfaces with independent floating main/detail panels and Settings content, with divider-free Settings navigation. Appearance settings can switch glass/solid materials, and reduced transparency preserves the floating layout.
- Give startup its own full-window layout, removing the two-tone frame inherited from chat padding while retaining explicit loading failures.
- Restore byte-identical backups of activated journals after relocation using full-content proofs, while preserving activation markers, event chains and evidence. Hash large files asynchronously in bounded chunks; normal reads do not rescan them.
- Correct the local packaging command to invoke the desktop package script. Update bilingual release notes, usage documentation and the website changelog.

## Data and validation boundaries

- Preserve existing tasks, conversations, evidence and other uncommitted work. Main-Bot context still defaults to public user interactions, with child execution details loaded on demand.
- A pre-seal RC25 backup requires certification against a genuine read-only source. If that source is unavailable, recovery remains blocked and the data is retained; matching size and timestamps alone are insufficient. RC26 prepares the proof in the original data directory so later complete backups can carry it.
- This operation publishes only; it does not install, replace or restart the running application. Users choose when to upgrade.
- Validate the final combined source with full regression, screenshot self-review and recovery through actual candidate-package modules over isolated data copies. Self-review is not independent review.
- Controlled cognition does not establish every cloud model's quality or latency. Native Windows/Linux installation flows, full screen-reader coverage and long-duration use remain outside this acceptance scope.
