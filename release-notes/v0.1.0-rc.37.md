## 发布说明

- **0.1.0-rc.37** 供负责人测试 Desktop 渲染 P0–P2，以及 rc.36 之后已经合入的其他修复。正式版仍为 0.0.18。

## 新功能

- `peer update` 按已安装通道检查 GitHub Releases，并安装该通道上的最新版本。stable、beta 与 rc 互不跨越。`peer update --check` 只报告，不安装。
- 增加 ADR 108 的基础 shell 命令：`peer sessions`、`peer models`、`peer doctor`、`peer completions` 与 `peer export`。`peer sessions delete` 同时移除该会话的目标计划；非交互删除必须带 `--yes`，交互终端会先询问。`peer models` 只读取本机已配置模型。`peer doctor` 检查本机安装，不改配置。`peer completions` 把 bash、zsh 或 fish 补全脚本写到标准输出，不修改 shell 配置。`peer export` 写出阅读副本，不是 Evidence；已有输出文件除非带 `--force` 否则保留。

## 修复与改进

- Desktop P0（#277）：经典会话发送与打开不再经 IPC 搬运全文历史。追加消息不回传消息数组；打开时读取尾部窗口，上翻再加载更早的页。上下文恢复复用当次发送快照，或在读取时让出，首屏不再被全文历史挡住。
- Desktop P2（#279）：会话列表使用只读物化预览。经典界面与 Bot 共用 Session Service。追加和消息更新写入有界预览；列表摘要读取该字段或尾部窗口，不再为列表扫描整份 JSONL。
- Desktop P1（#278）：流式回复按块渲染并保持滚动布局。可见文本按约 40ms 提交，已闭合的 Markdown 块保持不变；贴底跟随高度变化，而不是每一帧做命中测试。这不表示已经达到真实 Electron 手感。
- 用户锚点按宿主会话中的真实用户输入解析（#280）。被拒绝的锚点得到纠正后，恢复身份不再把未解析锚点算进失败指纹，可纠正的锚点错误不会在后续成功重试后继续挂起。真正的派发失败仍保留原责任，不会被改写成成功。
- 仓库要求实现前先阅读已记录的 ADR；书面边界发生变化时，先更新 ADR 再改代码（#282）。这是协作要求，不是新的运行时能力。
- TUI（#283）：机器人列表用光标标出当前项，并显示各自的名称、计数和一行预览。不再常驻 F2 或按键提示行。草稿恢复失败时输入框仍可编辑，输入区占满整行。这是现有 Bot TUI 壳上的呈现修复，不是 P3。
- 同步中英文发布说明、用户文档和站点更新日志。

## 升级与验证范围

- 延续联合协调格式 9。更新前保留完整数据备份。Desktop、CLI/TUI 与 Gateway 按同一版本说明升级。
- 升级矩阵保留已发布标签，并纳入本候选版本。发布检查、界面呈现与真实模型质量是不同的验收范围。本版不宣称真实 Electron 手感或真实模型质量，也不表示 P3、内网 Gateway 或远程配对已经交付。正式版仍为 0.0.18。

## Release notes

- **0.1.0-rc.37** is for owner testing of the Desktop rendering P0–P2 work, plus the other fixes already merged since rc.36. Stable remains 0.0.18.

## What's new

- `peer update` checks GitHub Releases and installs the newest build on the channel already installed. Stable, beta, and rc stay separate. `peer update --check` only reports the result.
- Add the basic shell commands from ADR 108: `peer sessions`, `peer models`, `peer doctor`, `peer completions`, and `peer export`. `peer sessions delete` also removes that session's goal plans. A non-interactive delete requires `--yes`; a terminal asks first. `peer models` reads the local model configuration. `peer doctor` checks the local install and does not change configuration. `peer completions` writes a bash, zsh, or fish script to stdout and does not edit shell configuration. `peer export` writes a reading copy, not Evidence, and keeps an existing output file unless `--force` is set.

## Fixes and improvements

- Desktop P0 (#277): classic send and open no longer ship the full history over IPC. Append omits the messages array. Opening reads a tail window, and scrolling up loads older pages. Context restore reuses the current send snapshot or yields while reading, so the first paint is not blocked on the full history.
- Desktop P2 (#279): session lists use a read-only materialized preview. Classic and Bot share one Session Service. Append and message updates write a bounded preview; list summaries read that field or a tail window instead of scanning the full JSONL.
- Desktop P1 (#278): streaming replies render by block and keep the scroll layout. Visible text commits about every 40ms, closed Markdown blocks stay unchanged, and stick-to-bottom follows the height change instead of hit-testing every frame. This does not establish a real Electron feel.
- Resolve user anchors against the real user input in the host conversation (#280). After a rejected anchor is corrected, recovery identity no longer hashes the unresolved anchor, so that correctable error does not stay pending once a later retry succeeds. A real dispatch failure keeps its original responsibility and is not rewritten as success.
- Require an ADR pass before implementation (#282). Read the recorded decision before changing code, and update the ADR first when a written boundary moves. This is a collaboration rule, not a new runtime capability.
- TUI (#283): the bot list marks the current row with a caret and shows each bot's name, counts, and one-line preview. Standing F2 and key-hint lines are gone. The composer stays editable if draft recovery fails, and the input spans the full row. This is presentation on the existing bot TUI shell, not P3.
- Update bilingual release notes, user documentation, and the website changelog.

## Upgrade and validation scope

- Retain combined coordination format 9 and a complete pre-update backup. Upgrade Desktop, CLI/TUI, and Gateway according to the same release instructions.
- The upgrade matrix keeps published tags and includes this candidate. Release checks, interface presentation, and real-model quality have different acceptance scopes. This release does not establish a real Electron feel or real-model quality, and it does not mean P3, an intranet Gateway, or remote pairing shipped. Stable remains 0.0.18.
