## 说明

- **Peer Agent 0.0.2** 是 `0.0.2-beta.1` → `0.0.2-beta.5` 整条 beta 线的正式毕业版（`latest` 通道），不是只记录 beta.5 增量。
- 本版把 Peer 从“能调用本地工具的聊天客户端”推进为任务流 Agent：先签收目标与边界，需要时追问，按复杂度规划，并用结构化 Evidence 与可执行成功标准关闭任务。
- 本地能力继续统一经过 Manifest → Runtime Projection → Tool Call → PermissionGrant → Evidence；模型文本不能替代真实执行结果。

## 重点能力

### 任务流与工作台

- **Agent / Plan / Goal 工作流**：Agent 默认自驱，Plan 在高风险副作用前提供显式审阅；Goal runner 持久化计划图、子任务、暂停/恢复与 `waiting_user`。
- **可执行成功标准（DoD-as-Code）**：命令、测试、文件存在/内容检查等标准必须实际执行并附着 `criterionResults` / `evidenceRefs` 后，目标才可关闭。
- **结构化追问与签收**：任务先形成目标、边界与成功标准；缺少关键产品决策、权限或高风险取舍时再中断用户。
- **全局 Workbench**：集中展示推进中任务、待验收结果、历史与后台 shell 线程；支持任务总览、历史抽屉、继续同一任务和结果验收。
- **长任务连续性**：Goal 状态、上下文压缩、continuity source 与 prompt checksum 支持跨中断续跑，同时不把摘要当成 Evidence。

### Automation 与可见执行

- **对话内创建 Automation**：从自然语言识别周期工作，生成结构化提案，只有用户确认后才创建，并返回真实创建回执。
- **隔离仓库运行**：自动化可在独立 Git worktree 中执行，返回 commit/diff artifact refs 与回执，避免静默污染当前 checkout。
- **内嵌 Browser / Workbench**：网页导航、点击、输入、DOM 与截图读取在可见 Browser 中执行，并继续受 PermissionGrant + Evidence 治理。
- **结果查看与托盘状态**：Automation 运行结果、状态与历史可在客户端查看。

### Open Runtime、扩展与多端

- **Open Runtime**：发布宿主中立的 `@peer-agent/protocol`、`@peer-agent/runtime-core`、`@peer-agent/runtime-sdk`，其他 Node 宿主可复用同一能力投影、授权、执行与 Evidence 管线。
- **一个核心，多种表面**：Desktop、TUI 与 `peer` CLI 共享运行时、System Context、会话数据与 `~/.peer-agent` 配置。
- **MCP / Plugin / Skill**：MCP 管理与工具开关、SkillHub、技能详情/胶囊、工具定义、Provider channel 接线与卸载路径持续完善。
- **CLI / TUI**：npm 包安装平台 `peer` 二进制；TUI 补齐 `/version`、运行反馈与共享会话/设置体验。
- **Provider 连接中心**：官方 API、自定义兼容、授权登录与多种 Coding Plan / 第三方 Provider 模板继续统一管理。

### 稳定性与体验

- 修复流式滚动、上下文用量恢复、Provider stream metadata、Qoder 本地授权错误、Kimi reasoning、Automation 幂等与验收队列脏状态等问题。
- 增加 prompt-prefix 稳定与缓存指标，补齐 ChatGPT Responses cache-hit token 统计。
- 优化工作区树、输入区、模型条、Skill 入口、任务卡片、用量图表与结果验收动效。

## 安装与升级

- **Desktop**：从 GitHub Releases 的 `v0.0.2` 资产安装对应平台包。
- **CLI / TUI**：`npm i -g @peer-agent/cli@latest`（或 `npm i -g @peer-agent/cli@0.0.2`）。
- `peer --version` 应输出 `peer 0.0.2`。
- 从 `0.0.1` 或任意 `0.0.2-beta.*` 升级时，本地会话、Provider、MCP 与设置仍保存在 `~/.peer-agent`；建议升级前备份关键配置。

## 仍在规划

记忆体系、自进化 / 自迭代、完整多 Agent 协作、Agent swarm 与 Canvas 创作体系仍是路线图方向，**不属于 0.0.2 已交付能力**。

## Overview

- **Peer Agent 0.0.2** graduates the full `0.0.2-beta.1` → `0.0.2-beta.5` series to the `latest` channel; it is not just the beta.5 delta.
- This release moves Peer from a tool-capable chat client toward a Task Flow Agent: accept goals and boundaries, ask when material information is missing, plan by complexity, and close work with structured Evidence and executable success criteria.
- Local capabilities still follow Manifest → Runtime Projection → Tool Call → PermissionGrant → Evidence. Model prose cannot substitute for execution results.

## Highlights

### Task flow and workbench

- **Agent / Plan / Goal workflows**: Agent is self-driven by default; Plan gates high-risk side effects; Goal runner persists plan graphs, subtasks, pause/resume, and `waiting_user`.
- **Definition of Done as code**: command, test, file-exists, and file-contains criteria must run and attach `criterionResults` / `evidenceRefs` before a goal can close.
- **Structured intake and follow-up questions**: goals become objectives, boundaries, and success criteria; missing product decisions, permissions, or risky trade-offs interrupt the user instead of being guessed.
- **Global Workbench**: centralizes advancing tasks, results awaiting acceptance, history, and background shell threads; includes task overview, history drawers, continue-task flow, and result acceptance.
- **Long-task continuity**: persisted Goal state, compaction, continuity sources, and prompt checksums support resuming after interruptions without treating summaries as Evidence.

### Automation and visible execution

- **Create Automation from conversation**: detect recurring work, show a structured proposal, create only after confirmation, and return a real receipt.
- **Isolated repository runs**: Automation can use a dedicated Git worktree and return commit/diff artifact refs instead of silently mutating the active checkout.
- **Embedded Browser / Workbench**: navigation, clicks, typing, DOM reads, and screenshots happen in a visible Browser under PermissionGrant + Evidence.
- **Run results and tray state**: inspect Automation status, history, and results in the client.

### Open Runtime, extensions, and surfaces

- **Open Runtime**: publish host-neutral `@peer-agent/protocol`, `@peer-agent/runtime-core`, and `@peer-agent/runtime-sdk` so another Node host can embed the same projection, permission, execution, and Evidence pipeline.
- **One core, multiple surfaces**: Desktop, TUI, and the `peer` CLI share runtime, System Context, conversations, and `~/.peer-agent` configuration.
- **MCP / Plugin / Skill**: improve MCP management and tool toggles, SkillHub, skill detail/capsules, tool definitions, provider channel wiring, and uninstall paths.
- **CLI / TUI**: npm installs the platform `peer` binary; TUI adds `/version`, clearer runtime feedback, and shared sessions/settings.
- **Provider center**: continue unified management for official APIs, custom-compatible endpoints, OAuth sign-in, and coding-plan / third-party templates.

### Reliability and polish

- Fix streaming scroll, context-usage restoration, provider stream metadata, Qoder local-auth errors, Kimi reasoning, Automation idempotency, and stale acceptance-queue state.
- Add prompt-prefix stabilization and cache metrics, including ChatGPT Responses cache-hit token accounting.
- Refine the workspace tree, composer, model strip, skill entry points, task cards, usage charts, and result-acceptance motion.

## Install and upgrade

- **Desktop**: install the platform asset from the `v0.0.2` GitHub Release.
- **CLI / TUI**: `npm i -g @peer-agent/cli@latest` (or `npm i -g @peer-agent/cli@0.0.2`).
- `peer --version` should print `peer 0.0.2`.
- When upgrading from `0.0.1` or any `0.0.2-beta.*`, conversations, Providers, MCP, and settings remain under `~/.peer-agent`; back up critical configuration first.

## Still planned

The memory system, self-evolution / self-iteration, full multi-agent collaboration, Agent swarm, and Canvas creation system remain roadmap directions and are **not shipped in 0.0.2**.
