## 说明

- 本版本彻底修复 macOS / Linux 下常驻 `bash` 解释器因命令包含 `exit`、`set -e`/`set -u`、语法错误或单次命令超时而意外退壳并触发 `execution_outcome_unknown` 直接中止整个任务的问题。

## 修复

- **隔离常驻 Shell 中的 `exit` / `set -e` / `set -u` / `trap` 与语法错误**：
  - 在 `ShellSession` 命令帧构造层识别会终止或污染常驻 `/bin/sh` 的非引号词（`exit`、`return`、`trap`、`set -e`/`-u`/`-o`），自动在子 Shell `( command eval ... )` 中执行，并将普通命令升级为 `command eval` + 状态重置（`set +e +u`）；
  - 模型执行 `exit 0`、`exit 1`、`if ...; then exit 1; fi`、`set -e` 遇到失败或语法错误时，准确返回对应 `exitCode` 与已捕获输出，**不再关闭常驻 `/bin/sh`、不再触发 `shell_session_control_closed` / `execution_outcome_unknown`**；
  - 不含退壳指令的普通命令仍保留同进程 `cd`、`export` 与 Shell 函数持久化。
- **放宽默认 `bash` 超时并使前台超时可恢复**：
  - 将 `bash` 工具未传 `timeoutMs` 时的默认超时从 30 秒提升至 **120 秒**（上限仍为 600 秒）；
  - 前台命令命中 `shell_timeout` 且进程组已确认彻底收割（`ended == true`）时，向模型返回普通 `shell_timeout` 错误及已捕获的 `stdout`/`stderr`（而非一刀切熔断整个子任务），后续 `bash` 调用自动回退到独立子进程继续执行；
  - 仅在权限策略被撤销、或进程组无法确认停止时保留 `execution_outcome_unknown` 安全熔断。

## Notes

- This release fixes persistent foreground `bash` sessions on macOS/Linux aborting entire tasks with `execution_outcome_unknown` whenever a model runs `exit`, `set -e`/`set -u`, encounters a syntax error, or hits a single-command timeout.

## Fixes

- **Isolate `exit`, `set -e`/`set -u`, `trap`, and syntax errors in persistent `ShellSession`**:
  - Added quote-aware POSIX token detection in `CommandFrame` so commands invoking `exit`, `return`, `trap`, or `set -e`/`-u`/`-o` run inside `( command eval ... )`, while regular commands use `command eval` with `set +e +u` cleanup;
  - Commands like `exit 0`, `exit 1`, `if ...; then exit 1; fi`, `set -e` failures, and syntax errors now return their exact `exitCode` and captured output without terminating the persistent `/bin/sh` interpreter or triggering `shell_session_control_closed` / `execution_outcome_unknown`;
  - Regular commands continue to preserve `cd`, `export`, and shell functions across calls in the same interpreter.
- **Increase default `bash` timeout and make foreground `shell_timeout` recoverable**:
  - Raised default `bash` timeout when `timeoutMs` is omitted from 30s to **120s** (max remains 600s);
  - When a foreground shell command hits `shell_timeout` and its process group is confirmed stopped, return a recoverable `shell_timeout` tool failure with captured `stdout`/`stderr` instead of killing the entire worker task, and fall back seamlessly to isolated per-command execution for subsequent `bash` calls;
  - Preserve `execution_outcome_unknown` when permission policy is revoked mid-flight or process termination cannot be confirmed.
