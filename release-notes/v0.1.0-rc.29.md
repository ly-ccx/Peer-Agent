## 发布说明

- **0.1.0-rc.29** 基于 RC28，补齐主 Bot 对子任务的持续监督、返修与撤回收口，并修复历史恢复被卡住的问题。正式版仍为 0.0.18。

## 修复与优化

- 子 Agent 的普通问题、技术中断、核验与返修先回到主 Bot；未回答的问题不会因对话变长而丢失。已交回但未签收的结果可在原任务、原成功标准内返修，保留历史成果、Evidence 与预算；用户停止、人工确认和签收规则保持有效。
- 后续提问会看到同一 Bot 尚未结清的任务。汇报这些任务时必须引用原任务并保留其跟进责任，不再以无来源的普通文本结束。
- 明确表示“不再需要”时，可以取消已交回但未签收的旧任务；撤回委托后不再一直占用“当前任务”。历史未知结果如实保留，撤回不代表旧命令成功或外部影响已回滚。
- 中断的委派任务保留恢复责任和真实失败原因，不再把未知中断说成断网，也不把参数错误误判为需要新授权。
- 修复超长历史事件编号导致“保全历史并安全继续”始终失败的问题。恢复入口只在仍有待处理项时显示，可在确认数量后一次结束全部旧执行；准入后的复查不再重写已接收输入备份。维护失败后会按最新记录重新核对。
- 主对话为每个子 Agent 保留一行活动并原位更新状态；图标不再跳动，减少动态效果时静态呈现。引用预览改为来源与摘录两层显示。查看任务流程时隐藏输入区；已有真实终态的授权卡不再重新出现按钮；技能安装范围统一称“机器人”。
- 页面、设置和低频功能按需加载，隐藏视图不重复读取；TUI 的 help、version 与 exec 不再先加载交互模块。
- 官网首页、使用文档与中英文 README 改为围绕项目 Bot 介绍；同步中英文发布说明与网站更新日志。

## 升级与限制

- 升级前备份完整数据根，Desktop、CLI/TUI 与 Gateway 一同升级。新的监督记录要求最低读写格式 5，首次写入新的监督语义后提升到 6；旧版本无法继续写入或处理这类数据。回退必须使用完整升级前备份，不能手改版本。
- 无法确认的执行结果与外部副作用继续受保护，不提供模型自证成功或强制清账入口。已汇报但核验未通过的结果继续由主 Bot 跟进修复，连续无进展后转为可恢复的阻塞提示。
- 本次发布不安装或重启当前应用，不操作原设备上的真实任务。回归使用隔离数据与受控认知，不代表真实供应商的多轮监督质量、完整硬件输入法/读屏、所有平台安装交互或长期日用已覆盖。

## Release notes

- **0.1.0-rc.29**, based on RC28, completes the main Bot's ongoing supervision, repair and withdrawal of child tasks, and fixes history recovery that could stay blocked. Stable remains 0.0.18.

## Fixes and improvements

- Route ordinary child-Agent questions, technical interruptions, verification and repair to the main Bot first, and keep unanswered questions available as the conversation grows. Repair a returned but unaccepted result within its original task and success criteria, preserving prior results, Evidence and budget. User stops, human confirmations and acceptance rules remain in force.
- Show follow-up turns the unresolved tasks of the same Bot. Reports about them must cite the original task and keep its follow-up obligation instead of ending as source-free text.
- Cancel a returned but unaccepted task when you say it is no longer needed. A withdrawn delegation no longer stays in Current Tasks. Unknown historical outcomes remain recorded; withdrawal does not mean earlier commands succeeded or that external effects were rolled back.
- Keep recovery ownership and the actual failure cause for interrupted delegated work, without reporting an unknown interruption as a network loss or treating an argument error as a new authorization requirement.
- Fix history recovery that kept failing on oversized historical event IDs. The recovery entry appears only while something still needs handling and can end all earlier executions after confirming their count. Rechecks after admission no longer rewrite the received-input backup, and a failed maintenance step rechecks against the latest records.
- Keep one activity row per child Agent in the main conversation and update its state in place. Icons no longer bounce and stay static with reduced motion. Quote previews show the source and excerpt on two lines. Task-flow viewing hides the composer, authorization cards with a real terminal state no longer show their buttons again, and skill installation scope consistently refers to the Bot.
- Load pages, settings and infrequent features on demand, and stop repeated reads from hidden views. TUI help, version and exec no longer load interactive modules first.
- Rewrite the website home page, user documentation and bilingual READMEs around project Bots, and update bilingual release notes and the website changelog.

## Upgrade and limits

- Back up the complete data root before upgrading Desktop, CLI/TUI and Gateway together. New supervision records require minimum reader/writer format 5, raised to 6 after the first write with the new supervision semantics; older versions cannot write or process such data. Rollback requires the complete pre-upgrade backup, without editing versions by hand.
- Unconfirmed execution outcomes and external side effects stay protected, with no model self-certification or forced settlement. A reported result that failed verification stays with the main Bot for repair and becomes a recoverable blocker after repeated lack of progress.
- Publication does not install or restart your app or operate real tasks on the original device. Regression uses isolated data and controlled cognition, without claiming real-provider multi-round supervision quality, full hardware IME/screen-reader coverage, every platform's installation interactions or long-duration acceptance.
