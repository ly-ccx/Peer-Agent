- 本文是 **0.1.0-rc.2 发布候选版**；正式版尚未发布。当前候选版为 0.1.0-rc.2，正式通道仍为 0.0.18。

## 本次候选修复

- 机器人设置按外观、工作方式和模型分工分组；全局运行与额外模型角色按需展开，窄窗口与键盘操作纳入检查。
- macOS CLI 归档使用同次 Desktop 构建的已签名凭据助手，修复默认助手访问钥匙串超时的问题。
- 独立核验可读取真实成功命令的有限执行快照；失败、取消或未经授权的命令不会成为通过证据。
- 等待用户的任务收到回答后可恢复，前置依赖失败和待批准计划继续遵循原有准入门。
- GPT 订阅目录增加 GPT-6.1 Sol，原默认模型保持。

## 项目机器人

- 默认界面是机器人列表。绑定现有文件夹或新建受管机器人，每个项目保留稳定身份、独立头像、可选颜色与状态动效；可上传自己的图片。
- 对话中直接交代需求。机器人负责只读理解与任务调度，写入由有边界和成功标准的任务执行；收到输入、执行完成、核验、签收和合回分别表达。
- 档案按需打开，包含概况、任务与历史、目标、记忆和设置。全语料搜索可定位消息、任务和记忆；长对话按页读取，引用定位后可以返回最新。

## 任务 记忆 模型与目标

- 独立 Git 隔离任务可以并行；读写槽位、优先级、失败依赖、插话与取代遵循调度边界。进程中断后按持久事实恢复，等待用户的任务不会自行继续。
- 记忆保留来源、种类、信任与状态，可查看、过滤、分页、撤销和导出。项目开关与全局开关决定准入；经验不能放宽权限。
- 模型按档位与角色分工，主模型和回退模型按能力选择；实际调用计入用量。
- 持续目标支持只报告、先提议和授权范围内自行推进；只读定时、Git、文件与 CI 探测记录真实观察，无变化不重复打扰。
- 主动性、安静时段与今日小结可配置。需要判断或批准时递卡片，结果关联真实来源。

## 多入口与诊断

- `peer` 在已绑定项目打开对应机器人，`peer bots` 显示列表。桌面持有租约时 TUI 提交到同一队列；桌面退出后终端可接管，一个项目同时只有一个宿主。
- Gateway 提供“我的机器人”、分页对话、任务摘要和文本消息；按账户、设备绑定与每台机器人查看/消息授权校验。离线不代发或隐藏排队。
- 设置 → 开发者可刷新并导出诊断 JSON，显示队列、租约、最近事件、调度、目标探测与回合时长。正文与身份只保留长度和 hash，绝对工作区路径不导出。
- 键盘导航、档案焦点进入与归还、中英文、减少动效及多主题对比度已纳入回归。200 机器人、1 万消息、10 万事件与1万记忆有可重复规模检查。

## 升级 经典界面与降级

- **Desktop、CLI/TUI 和 Gateway 同时升级**。先退出旧宿主；旧 TUI 不理解新租约，不能与新宿主同时操作同一数据根。
- 设置 → 通用 → 界面可切回经典界面；旧会话保留在机器人档案 → 任务 → 历史对话，全局历史保留无项目会话。
- 升级前备份完整数据根。迁移保存设置备份与稳定项目 ID，不批量改写旧会话。降级到 0.0.18 时先退出新版本；旧版忽略新机器人/目标状态，目标停止推进。再升级保留原身份、会话、档案、记忆与目标。

## 已知限制与验收范围

- 远程仅文本，最多 4000 个 Unicode 字符；不支持附件、远程文件操作或批准。未知送达状态的重试 ID 只保留在当前网页内存；刷新后先到电脑核对。
- 远程设备身份目前使用 macOS 钥匙串；其他桌面平台没有该身份适配，不回退为明文密钥。电脑必须在线。
- 隔离写任务需要 Git；外部副作用仍须授权。目标 token 硬限尚未实现，会拒绝该配置。
- SVG 默认头像有状态动效；上传的用户图片是静态图片，不会自动生成表情动画。
- GPT-6.1 Sol 已加入目录与保存回归；本机订阅实测目前返回空内容，实际可用性仍待复验，不作为通过项。
- 源码、自动化、控制网络和已验证 macOS 安装包分别列证据；它们不替代真实手机、生产账户部署、所有平台交互安装与负责人七天日用。

## Release status

- This is the **0.1.0-rc.2 release candidate**. Stable has not been published. The candidate is 0.1.0-rc.2; the stable channel remains 0.0.18.
- Developer RC validation precedes comprehensive owner testing and seven days of daily use. Stable publication requires owner confirmation after fixes.

## Fixes in this candidate

- Bot settings are grouped by appearance, work style and model roles. Global runtime controls and extra roles expand on demand; narrow layouts and keyboard interaction are covered.
- macOS CLI archives use the signed credential helper from the same Desktop build, addressing the default helper's keychain timeout.
- Independent verification can read bounded snapshots of actual successful commands. Failed, cancelled or unauthorized commands cannot become passing evidence.
- Answers resume tasks that are waiting for user input. Failed dependencies and plans awaiting local approval retain their admission gates.
- The GPT subscription catalog includes GPT-6.1 Sol while preserving the existing default.

## Project bots

- The default interface is a bot list. Bind existing folders or create managed bots, with stable project identity, distinct avatars, selectable colors and state animation. Custom image uploads are supported.
- Give requests in the project conversation. The bot handles read-only understanding and task coordination. Scoped tasks perform writes with success criteria. Receipt, execution, verification, acceptance and integration are separate states.
- Profiles expose overview, tasks and history, objectives, memory and settings. Corpus search finds messages, tasks and memory. Long conversations are paginated; quotations locate older messages and can return to the latest.

## Tasks memory models and objectives

- Independent Git worktree tasks can run in parallel. Slots, priority, failed dependencies, interruptions and supersession follow scheduler boundaries. Durable facts drive crash recovery; tasks waiting for a user do not resume silently.
- Memory retains sources, kind, trust and status. Review, filter, page, revoke and export entries. Global and project switches control admission; learned experience cannot expand permissions.
- Model tiers and roles select capable primary and fallback models, with usage recorded for actual calls.
- Continuous objectives support report, propose and authorized action. Read-only schedule, Git, file and CI probes record actual observations and avoid repeated unchanged notifications.
- Proactivity, quiet hours and daily digests are configurable. Decisions and approvals produce cards; reports link to actual sources.

## Multiple surfaces and diagnostics

- `peer` opens the bot for a bound project; `peer bots` lists bots. TUI uses the same queue while Desktop holds the lease, and can take over after Desktop exits. Each project has one host.
- Gateway offers My bots, paginated conversations, task summaries and text input, governed by account, device binding and per-bot viewing/messaging grants. Offline requests are not queued secretly.
- Settings → Developer refreshes and exports diagnostics for queues, leases, recent events, scheduler slots, objective probes and turn timing. Text and identities use length/hash; absolute workspace paths are excluded.
- Keyboard navigation, profile focus, both locales, reduced motion and theme contrast are covered by regression checks. Scale tests use 200 bots, 10,000 messages, 100,000 events and 10,000 memories.

## Upgrade classic interface and downgrade

- **Upgrade Desktop, CLI/TUI and Gateway together.** Quit old hosts first. Older TUI versions do not understand the new lease and must not share a data root with new hosts.
- Settings → General → Interface restores the classic UI. Profile → Tasks → History retains old conversations; global history retains conversations without a project.
- Back up the full data root before upgrading. Migrations back up settings and preserve stable identities without rewriting old conversations. Quit the new version before downgrading to 0.0.18, which ignores new bot/objective state and stops objective advancement. Re-upgrading retains identities, conversations, profiles, memory and objectives.

## Known limits and acceptance scope

- Remote input is text only, up to 4,000 Unicode characters. Attachments, remote file operations and approvals are unavailable. Unknown-delivery retry IDs live in the current page memory; check the computer after reloading.
- Remote device identity currently requires macOS Keychain. Other desktop platforms have no identity adapter and do not fall back to plaintext keys. The computer must be online.
- Isolated writes require Git; external side effects require authorization. Objective token hard limits are rejected because they are not implemented.
- Default SVG avatars animate with state. Uploaded images remain static and do not acquire generated facial animations.
- GPT-6.1 Sol catalog selection and persistence are covered. Current local subscription checks returned empty output; actual usability remains unverified.
- Source, automated, controlled-network and verified macOS installed-client evidence are reported separately. They do not replace a physical phone, production identity deployment, interactive installation on every platform or owner daily use.
