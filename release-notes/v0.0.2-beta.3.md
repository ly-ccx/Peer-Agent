## 说明

- **0.0.2-beta.3** 强化 Automation 运行结果的可见性、可追溯性与通知控制，并继续打磨自动化提案和输入框体验。
- Automation 仍以 Fresh Run 和隔离 worktree 执行；不可变 Run Receipt 是结果真相，Conversation 用于查看过程和继续追问。
- 本版不改变本地能力执行、显式授权与 Evidence 边界。

## 新功能

- **持久化 Automation 结果**：Run Receipt 现在会保存最终结果摘要；模型未提供结构化摘要时，会从最终 assistant 消息回填，并为无正文的成功运行提供明确说明。
- **最近结果入口**：Automation Overview 和系统托盘展示最近运行及摘要，可直接打开对应的精确 Run。
- **运行结果对比**：Receipt 显示当前结果与上一次完成结果是否变化，并保留受控的上一结果摘要。
- **仅变化时通知**：成功通知新增“仅结果变化时通知”选项，避免相同结果反复打扰。
- **Automation 会话归属**：Fresh Run 会话展示可点击的 Automation 来源徽章；隔离 worktree 中生成的会话也会投影到发起任务的原始 workspace。

## 优化

- Automation Runs 和当前打开的 Receipt 会在运行状态变化后实时刷新。
- 已完成、失败或取消的 Automation 提案默认折叠；确认或取消后会清理提案卡片。
- Automation 活跃状态使用更清晰的绿色状态标签。
- 收紧首页输入框控制条间距，并避免 Automation 提案卡片被弹性布局压缩。

## 修复

- Runner 不可用或异步启动失败时，Run 会进入可见失败终态并生成失败 Receipt，不再静默停留。
- Automation 提案卡片清理后，重复确认仍会返回原 Receipt，而不会重复创建 Automation。
- Automation 终态会正确更新 `lastRunAt`；系统任务通知不会误触发 intake contract 路径。

## CLI（仅命令行）

- 本版 GitHub Release 附带 CLI 归档（与 Desktop 同 tag / 同版本）。
- 资产示例：`peer-darwin-arm64.tar.gz`（内含 `peer` + `peer-credential-helper`，**必须同目录**）。
- 安装方式：
  - **npm（有 `NPM_TOKEN` 且 publish 成功时）**：`npm i -g @peer-agent/cli@beta`（或 `pnpm add -g @peer-agent/cli@beta`），`postinstall` 自动拉本版归档。
  - **手动**：解压归档后将目录加入 `PATH`，执行 `peer --version` 校验，再运行 `peer`。
- 可不装 Desktop；会话与设置仍落在 `~/.peer-agent`，与客户端共享。

## Notes

- **0.0.2-beta.3** makes Automation run results easier to find, trace, compare, and control, while continuing to polish Automation proposals and the composer experience.
- Automations still execute as Fresh Runs in isolated worktrees. The immutable Run Receipt is the result source of truth; Conversations preserve execution context and follow-up discussion.
- Local capability execution, explicit authorization, and Evidence remain unchanged.

## What's New

- **Durable Automation results**: Run Receipts now retain the final result summary. When the model does not provide a structured summary, Peer Agent falls back to the final assistant message and supplies an explicit success fallback when no body is available.
- **Recent-result entry points**: Automation Overview and the system tray show recent runs and summaries, with direct navigation to the exact Run.
- **Result comparison**: Receipts show whether the current result changed from the previous completed result and retain a bounded previous-result summary.
- **Notify only on change**: successful-run notifications can now be limited to changed results to suppress repeated identical updates.
- **Automation conversation origin**: Fresh Run chats expose a clickable Automation origin badge, and conversations created in isolated worktrees are projected back to the workspace that launched the Automation.

## Improvements

- Automation Runs and the currently open Receipt refresh when runtime state changes.
- Completed, failed, or cancelled Automation proposals collapse by default, and proposal cards clear after confirmation or cancellation.
- Active Automation states use a clearer green status pill.
- Home composer control spacing is tighter, and Automation proposal cards no longer flex-collapse.

## Fixes

- Missing runners and asynchronous runner startup failures now produce visible failed Runs and failure Receipts instead of remaining silent or stuck.
- Reconfirming an Automation proposal after its card is cleared returns the original Receipt without creating a duplicate Automation.
- Automation terminal states update `lastRunAt` correctly, and system-task notifications no longer enter the intake-contract path.

## CLI (command-line only)

- This GitHub Release also ships CLI archives (same tag / version as Desktop).
