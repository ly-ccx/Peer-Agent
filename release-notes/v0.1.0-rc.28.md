## 发布说明

- **0.1.0-rc.28** 基于 RC27，集中修复子任务核验停滞，并补齐普通用户可操作的历史恢复与安全续跑。正式版仍为 0.0.18。

## 修复与优化

- 子任务的验收依据不足时，通过原任务的有界修复流程补齐，不因反复核验长期占住任务；保留核验记录、已有成果和明确的停止边界。
- 聊天恢复提示提供“检查并恢复”。另一实例占用时可请求安全接手；恢复前等待在途操作停止，保全两条原始历史、已接收输入和普通、原生及子任务检查点。
- 只有原任务身份、完整检查点与操作回执吻合时才续跑。旧输入保持归属，已结束工作保持终态；未知执行结果、未确认送达或交接单独隔离，不自动重放，也不永久阻塞无关新对话。
- 用户可明确选择“保留成果并结束旧执行”，确认后保留报告、工作树、检查点和用量回执。旧任务不能绕过隔离自动验收、合回或清理；恢复中断、来源变化和停止超时均有复查入口。
- 改善证据卡片的紧凑排版与间距；版本显示在 Peer 名称下，更新入口位于新建按钮旁。
- 同步中英文发布说明、README、使用文档及网站更新日志。

## 升级与限制

- 升级前备份完整数据根，Desktop、CLI/TUI 与 Gateway 一同升级。新历史准入要求最低 reader/writer 4；旧版拒绝这种数据。回退必须使用完整升级前备份，不能手改版本或从保留旧日志继续写入。
- 无法自动确认的归属或送达冲突仍保持暂停，可导出诊断联系支持。历史恢复准入与宿主实际就绪分开表达，不把未知操作标成成功。
- 本次发布不安装或重启当前应用，不操作原设备上的真实卡住任务。回归使用隔离数据与受控认知，不代表真实供应商质量、完整硬件输入法/读屏、所有平台安装交互或长期日用已覆盖。

## Release notes

- **0.1.0-rc.28**, based on RC27, fixes stalled child-task verification and adds user-operated history recovery and safe continuation. Stable remains 0.0.18.

## Fixes and improvements

- Repair missing acceptance evidence through bounded recovery of the original child task, preserving verification records, existing results and explicit stop boundaries.
- Open Check recovery from the conversation. Request a safe handoff when another instance owns execution; drain in-flight operations and preserve both original histories, received inputs and ordinary, native and child checkpoints before restoring.
- Continue only the original work with matching identity, complete checkpoints and execution receipts. Keep historical input ownership and terminal work intact. Isolate unknown execution outcomes, uncertain deliveries and unfinished handoffs without replaying them or blocking unrelated new conversations indefinitely.
- Explicitly keep results and end an earlier execution, preserving reports, worktrees, checkpoints and usage receipts. Isolation also prevents automatic acceptance, merging and cleanup. Recheck after interrupted maintenance, changed sources or incomplete stops.
- Improve evidence-card spacing and density. Show the version below Peer and place update controls beside New.
- Update bilingual release notes, READMEs, user documentation and the website changelog.

## Upgrade and limits

- Back up the complete data root before upgrading Desktop, CLI/TUI and Gateway together. New history admission requires minimum reader/writer version 4; older versions reject it. Rollback requires the complete pre-upgrade backup, without changing manifests or writing from retained legacy logs.
- Ownership or delivery conflicts that cannot be confirmed automatically remain paused; export diagnostics for support. History admission and actual host readiness are separate facts, and unknown operations are never marked successful.
- Publication does not install or restart your app or operate the original stuck task on another device. Regression uses isolated data and controlled cognition, without claiming real-provider quality, full hardware IME/screen-reader coverage, every platform's installation interactions or long-duration acceptance.
