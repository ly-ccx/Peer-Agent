## 说明

- **Peer Agent 0.1.0-beta.5** 是多入口预发布，走 beta 更新通道；正式版仍为 **0.0.18**。
- 桌面、TUI / CLI 和 Gateway 需要同时升级。本版之后进入 RC 自测与打磨，正式版等待负责人全面测试。

## 新增

- 在已绑定项目目录运行 `peer` 打开该机器人；`peer bots` 显示机器人列表，方向键与回车进入。`peer --classic` 保留经典界面，`peer exec` 保留原执行入口。
- 桌面持有项目租约时，TUI 作为客户端，把输入送到同一队列。桌面退出后，终端可以接管宿主；一个项目同时只有一个宿主。
- 终端支持任务、记忆、目标与接管命令，卡片以稳定编号定位。客户端的批准提示回到电脑处理。
- Gateway 的“我的机器人”页面支持机器人列表、分页对话、任务摘要和文本消息。远程请求经账户、设备绑定与本机授权校验；设备离线时不代发或排队。
- 设置 → 远程访问可为每台机器人分别开放“可查看”和“可发消息”，新机器人默认关闭，消息依赖查看。支持最近访问摘要、授权版本、重新连接与配对指引。
- 发消息遇到“可能已送达”时，网页保留原输入 ID 和正文，重试返回首次回执，电脑不会重复消费。

## 已知限制

- 远程只能发送最多 4000 字的文本，不支持附件、文件操作或远程批准；批准与执行留在电脑。电脑需在线并运行相同版本。
- 未确认消息暂存在当前网页内存；整页刷新或退出后应先在电脑核对是否已收到，再决定是否重新发送。
- 远程设备身份当前使用 macOS 钥匙串；其他桌面平台尚无该身份适配，不会退回明文密钥文件。
- TUI 客户端只能提交输入和查看；宿主接管需等待旧宿主释放租约，执行中任务会在下一宿主继续。
- 目标 token 硬限尚未实现并会拒绝该配置；隔离写任务需要 Git。外部副作用仍需授权。
- 自动化、源码 Electron 和浏览器手机宽度证据不替代所有平台的交互安装、真实手机 / 生产账户部署或连续日用验收。

## 升级与降级

- 退出所有旧宿主后升级桌面、CLI / TUI 和 Gateway。原机器人身份、会话与记忆保留；旧远程单工作区只迁移为该机器人的查看权限。
- 可在设置 → 通用 → 界面切回经典界面。降级到 0.0.18 前退出新版本；旧版忽略新目标和机器人运行态，持续目标停止推进。升级回来后稳定身份与原会话继续保留。

## Notes

- **Peer Agent 0.1.0-beta.5** is the multi-surface prerelease on the beta channel. Stable remains **0.0.18**.
- Upgrade Desktop, TUI / CLI and Gateway together. RC validation follows this release; the stable release awaits comprehensive owner testing.

## Added

- Run `peer` in a bound project to open its bot. `peer bots` provides keyboard navigation. `peer --classic` and `peer exec` retain their existing behavior.
- TUI operates as a client while Desktop owns the project lease, submitting to the same queue. After Desktop exits, the terminal can take over. Only one host runs each project.
- Terminal commands expose tasks, memory, objectives and takeover. Cards use stable numbers; client approvals direct users to the computer.
- The Gateway My bots page provides bot lists, paginated conversations, task summaries and text input. Account, device binding and local grants are checked. Offline devices do not receive queued or replayed requests.
- Remote access settings provide viewing and messaging grants per bot. New bots start closed; messaging requires viewing. Grant versions, activity summaries, reconnect and pairing instructions are visible.
- Unknown delivery outcomes preserve the original input ID and body. Retrying returns the first receipt and does not consume the input twice.

## Known limits

- Remote input is text only, up to 4000 characters. Attachments, file operations and remote approvals are unavailable. The computer must remain online; execution and approvals stay local.
- Unconfirmed input is retained in the current page memory. After a full reload or logout, check the computer before resending.
- Remote device identity currently uses macOS Keychain. Other desktop platforms have no identity adapter and do not fall back to plaintext secrets.
- TUI clients submit and view. Host takeover waits for the existing lease to be released; running tasks continue under the next host.
- Objective token hard limits are rejected because they are not implemented. Isolated writing needs Git; external side effects still require authorization.
- Automated, source Electron and mobile-width browser evidence do not replace interactive installation on every platform, a physical phone / production account deployment, or owner daily use.

## Upgrade and downgrade

- Quit old hosts before upgrading Desktop, CLI / TUI and Gateway. Stable bot identities, conversations and memory are retained. Legacy single-workspace remote settings migrate to viewing that bot only.
- Settings → General → Interface restores the classic UI. Quit the new version before downgrading to 0.0.18. Old versions ignore new bot and objective state and stop advancing continuous objectives. Re-upgrading retains identities and original conversations.
