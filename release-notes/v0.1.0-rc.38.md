## 修复与改进

- #288（`0496de222`）：大计划把 runner 进度写入 sidecar，不再每个 tick 整篇排版计划正文；本进程调度时忽略自己的进度日志。同一修复把会话预览回填收成一次索引写入，按线性时间读取 JSONL 尾部，并在稳定回合列表上缓存虚拟列表权重，避免主线程按会话重扫全文。
- #290（`3ee180f88`）：大计划上，生命周期没有真正变化的 tick，以及 `step_started` / `step_completed`，也写入 sidecar。无实际变化的 `setRunnerState` 不再清掉 sidecar 并重写正文，也不再追加 `.changes.jsonl`。真正的状态变化仍立即写回正文。
- #291（`71085b327`）：runner 仍在 running、exploring 或 compacting 时，状态、任务和契约都没变的 `persist()` 也走 sidecar。检查点生命周期在 `persist` 返回前同步刷写 sidecar，不重写正文；sidecar 保存并在重开 store 时还原 `runTraceCursor`（`activeNodeId` 与 `lastCheckpointNodeId`）。
- #292（`d69282e0`）：已停住的大计划在任务和正文契约未变时也跳过整篇 persist，不再追加 `changeKind=persist`。这包括 paused、waiting_user / interrupted，以及读路径把 completed 投影成 executing。状态真正变化仍立即写回正文。对 `d69282e0` 的本地 Electron 复测记为已修复。
- #285（`c258c944d`）：下载完成且进度对话框仍开着时关闭它。已经下载完成或失败之后，迟到的 100% 进度不再把阶段改回下载中。
- #287（`51d918deb`）：一条尚未落盘的任务记录不再让整个机器人列表显示为读取失败。展示路径跳过这条记录，其他机器人和其余任务仍可读；执行路径继续严格读取，不把不完整记录当成可执行事实。
- #289（`a15f4c9ff`，与 Knowledge #126 成对）：保留已落盘回合，并公平恢复失败工作。迟到的流终止不再用旧消息列表删掉下一回合的占位；失败叶子不再让已排队的恢复在真实执行前退出。安全接管只准备对应的本地失败叶子，并保留历史、完成步骤和证据。本地存储故障留在宿主阻塞，不进入模型网络重试。
- #286（`0ed7678e7`）：请求发往模型前，把超出上限的工具结果落到本地文件。模型侧只保留体积、路径和取回命令；写文件失败时退回预览，不把完整正文放到线上。外置之后，Layer 2 压缩仍由更早的超窗片段触发。bot-shell 的聊天详情不再在 `app.evaluate` 里读取屏幕。

## Release notes

- **0.1.0-rc.38** is for owner testing of the fixes landed after rc.37 (`156c959f`): the large-plan persist hang, the update dialog, torn task records, persisted-turn recovery, and spilling oversized tool results. Stable remains 0.0.18.

## Fixes and improvements

- #288 (`0496de222`): large plans write runner progress to a sidecar instead of pretty-printing the full plan body on every tick, and this process ignores its own progress journal when scheduling a sweep. The same fix batches session-preview backfill into one index write, reads the JSONL tail in linear time, and caches virtualization weight on the stable turn list, so the main thread no longer rescans a full transcript per conversation.
- #290 (`3ee180f88`): on large plans, ticks whose lifecycle fields did not actually change, plus `step_started` / `step_completed`, also go to the sidecar. A no-op `setRunnerState` no longer clears the sidecar and rewrites the body, and it no longer appends `.changes.jsonl`. A real status transition still writes the body immediately.
- #291 (`71085b327`): while the runner is still running, exploring, or compacting, an unchanged `persist()` also uses the sidecar. Checkpoint lifecycle sync-flushes the sidecar before `persist` returns, without rewriting the body. The sidecar stores and restores `runTraceCursor` (`activeNodeId` and `lastCheckpointNodeId`) when the store reopens.
- #292 (`d69282e0`): settled large plans also skip a full-body persist when tasks and body contracts are unchanged, so they no longer append `changeKind=persist`. That covers paused, waiting_user / interrupted, and a completed plan projected to executing on the read path. A real status change still writes the body immediately. The local Electron retest of `d69282e0` is recorded as fixed.
- #285 (`c258c944d`): close the update progress dialog when a download finishes while it is still open. A late 100% progress event after the update is already downloaded or has failed no longer puts the phase back into downloading.
- #287 (`51d918deb`): one task record that has not landed on disk no longer makes the whole bot list show as a read failure. The display path skips that record, so other bots and the remaining tasks stay readable. The execution path keeps the strict read and does not treat the incomplete record as an executable fact.
- #289 (`a15f4c9ff`, paired with Knowledge #126): preserve persisted turns and resume failed work fairly. A late stream terminal no longer deletes the next turn's placeholder from an older message list, and a failed leaf no longer makes queued recovery exit before real execution. A safe takeover prepares only the matching local failed leaf and keeps history, completed steps, and evidence. A local storage fault stays host-blocked and does not enter a model network retry.
- #286 (`0ed7678e7`): spill oversized tool results to local files before the model request. The model side keeps the size, path, and a command to read the file back. If the write fails, the request falls back to a preview and does not send the full body. After the spill, Layer 2 compaction is still triggered by older over-budget slices. Bot-shell chat details no longer read the screen inside `app.evaluate`.
