- #288（`0496de222`）：大计划把 runner 进度写入 sidecar，不再每个 tick 整篇排版计划正文；本进程调度时忽略自己的进度日志。同一修复把会话预览回填收成一次索引写入，按线性时间读取 JSONL 尾部，并在稳定回合列表上缓存虚拟列表权重，避免主线程按会话重扫全文。
- #290（`3ee180f88`）：大计划上，生命周期没有真正变化的 tick，以及 `step_started` / `step_completed`，也写入 sidecar。无实际变化的 `setRunnerState` 不再清掉 sidecar 并重写正文，也不再追加 `.changes.jsonl`。真正的状态变化仍立即写回正文。
- #291（`71085b327`）：runner 仍在 running、exploring 或 compacting 时，状态、任务和契约都没变的 `persist()` 也走 sidecar。检查点生命周期在 `persist` 返回前同步刷写 sidecar，不重写正文；sidecar 保存并在重开 store 时还原 `runTraceCursor`（`activeNodeId` 与 `lastCheckpointNodeId`）。
- #292（`d69282e0`）：已停住的大计划在任务和正文契约未变时也跳过整篇 persist，不再追加 `changeKind=persist`。这包括 paused、waiting_user / interrupted，以及读路径把 completed 投影成 executing。状态真正变化仍立即写回正文。

## Release notes

- **0.1.0-rc.38** is for owner testing of the Desktop large-plan persist hang fixes landed after rc.37. Stable remains 0.0.18.

## Fixes and improvements

- #288 (`0496de222`): large plans write runner progress to a sidecar instead of pretty-printing the full plan body on every tick, and this process ignores its own progress journal when scheduling a sweep. The same fix batches session-preview backfill into one index write, reads the JSONL tail in linear time, and caches virtualization weight on the stable turn list, so the main thread no longer rescans a full transcript per conversation.
- #290 (`3ee180f88`): on large plans, ticks whose lifecycle fields did not actually change, plus `step_started` / `step_completed`, also go to the sidecar. A no-op `setRunnerState` no longer clears the sidecar and rewrites the body, and it no longer appends `.changes.jsonl`. A real status transition still writes the body immediately.
- #291 (`71085b327`): while the runner is still running, exploring, or compacting, an unchanged `persist()` also uses the sidecar. Checkpoint lifecycle sync-flushes the sidecar before `persist` returns, without rewriting the body. The sidecar stores and restores `runTraceCursor` (`activeNodeId` and `lastCheckpointNodeId`) when the store reopens.
- #292 (`d69282e0`): settled large plans also skip a full-body persist when tasks and body contracts are unchanged, so they no longer append `changeKind=persist`. That covers paused, waiting_user / interrupted, and a completed plan projected to executing on the read path. A real status change still writes the body immediately.
