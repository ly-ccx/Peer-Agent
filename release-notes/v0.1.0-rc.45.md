## 说明

- 本版本完成了项目 Bot 统一调度、原位续作与自然回复体系重构（ADR 138），并全面解除多图/高清截图传输瓶颈，彻底解决「任务跑完反复查看报告、追问失忆重开、带高清图发送卡死或与后台任务互相阻塞」等体验问题。

## 新增与改进

- **自然语言直出回复与无闪烁 `NO_REPLY` 静默协议**：
  - 主 Bot 默认直接以自然语言回复用户，宿主自动补全 `replyTo`、关联任务 `sources`、状态声明、OpenUI 交互卡片与 Host Evidence 引用，并自动完成已汇报结果的结算（`post_reply` 保留为结构化提问/覆写可选工具）；
  - Rust 与 TypeScript 共用 12 组真值表契约识别 `NO_REPLY` 静默标记，并在 4 套模型流式解码器接入 `ToolIntent` 信号，桌面端与 TUI 全程无 `NO_R` 闪烁且不留空气泡；用户回合严禁静默吞消息。
- **内联唤醒报告（Wake Envelope）消除多轮空转**：
  - 后台子任务完成、失败或提问时，宿主将 Worker 正文、改动文件、OpenUI 产物与失败原因按优先级去重、安全转义并受控截断后直接内联到唤醒上下文中，主 Bot 单次模型请求即可直出汇总汇报，不再反复空转调用 `get_session`。
- **同 Worker 原位续作（Follow-up）与运行中纠偏（Steer）**：
  - 扩展 `message_session` 支持 `intent: "followup"`、`expectedEpoch` 乐观锁与多图附件透传；用户对刚完成的子任务追问修改时，优先复用原 Worker 对话与工作区原位继续，并在模型切换或环境不可复用时安全降级新开；
  - 支持对运行中 Worker 进行中途纠偏（`pendingSteerSeq` 注入与尾竞态保护），桌面端对话流复用原任务行不刷重复条目。
- **单真源终态发射、增量上下文与失败暂挂（Failure Hold）**：
  - 终态 `session_ended` 统一由 `SessionSupervisor` 单点持久化并支持崩溃幂等重放，`WatchPublisher` 收窄为仅发射 `progress` / `needs_user` / `stalled`，消除重复唤醒与重复回复；
  - 新增会话级区块指纹增量上下文与 1.5s 外读硬超时降级，压缩长对话重复 Token；
  - 命中 `429`（遵循 `Retry-After` / 指数退避）、熔断开启或鉴权拒绝时自动暂挂后台唤醒队列，用户发新消息、手动重试或切换模型后立即恢复。
- **支持 100 张 8K 高清图外置存储与 64 MiB RPC 帧传输**：
  - 单消息附件上限提升至 100 张、单图支持至 32 MiB、整包传输上限 512 MiB，超过 32 KiB 的图片自动外置落盘为内容寻址文件（`attachment-blobs/`），并在发送给模型前按需加载且支持后台子任务并行运行不卡顿；
  - 放宽核心 RPC 单帧上限至 64 MiB，修复超限报错丢失请求 `id` 导致前端挂等 30s 超时的问题；同时升级 `attachments` 编解码为单次 `base64` 处理，并保留上游模型真实错误详情。

## Notes

- This release delivers the unified Project Bot scheduling, in-place Worker follow-up, and natural reply architecture (ADR 138), alongside out-of-line 100×8K high-resolution image transport and 64 MiB RPC framing to eliminate multi-round wake ping-pong, amnesiac retries, and large-attachment stalls.

## Highlights

- **Natural Replies by Default & Flicker-Free `NO_REPLY` Protocol**:
  - Main Bot now delivers user replies and wake summaries directly in natural text while the host automatically binds `replyTo`, `sources`, `statusClaims`, OpenUI interactive cards, and host evidence and settles reported sessions (`post_reply` remains optional for structured quick-reply options or explicit overrides);
  - Shared Rust/TypeScript 12-case `NO_REPLY` contract and `ModelDelta::ToolIntent` streaming suppression across all 4 wire decoders prevent partial sentinel flicker in both Desktop and TUI, while guaranteeing direct user turns never silently drop messages.
- **Inline Wake Envelope (Single-Round Completion Reporting)**:
  - Host embeds deduplicated, XML-escaped, and UTF-8-bounded worker output, changed files, interactive artifacts, and failure details directly into the wake prompt so Main Bot reports results in a single model turn without extra `get_session` roundtrips.
- **Same-Worker In-Place Follow-Up & Mid-Turn Steering**:
  - Extended `message_session` with `intent: "followup"`, `expectedEpoch` optimistic locking, and wire-hydrated workspace image attachments to resume completed/failed workers in their existing conversation and workspace (with safe `started_fresh` fallback when checkpoints/workspaces/models change);
  - Added mid-turn steering via `pendingSteerSeq` with post-episode late-steer race protection, and deduplicated reused inline task rows in Desktop threads.
- **Single-Source Terminal Events, Delta Context, & Failure Hold**:
  - `SessionSupervisor` is now the sole publisher of `session_ended` (with crash-safe `terminalEvent` replay), while `WatchPublisher` emits only non-terminal `progress`, `needs_user`, and `stalled` signals;
  - Added per-conversation section-fingerprint delta context with 1.5s read timeouts, plus workspace `FailureHold` for `429` (`Retry-After` / exponential backoff), `CircuitOpen`, and `AUTH_REJECTED` to stop wake retry storms.
- **100×8K Out-of-Line Image Attachments & 64 MiB RPC Framing**:
  - Raised attachment admission to 100 images per message (up to 32 MiB each, 512 MiB wire budget), storing images larger than 32 KiB out-of-line in content-addressed workspace blobs with single-pass base64 handling so large uploads stay responsive even while background workers run;
  - Raised core RPC frame limit to 64 MiB, preserved caller `id` on frame-limit errors to eliminate 30s client timeouts, and surfaced sanitized upstream provider error details.
