## 发布说明

- **0.1.0-rc.36** 修复等待、停止与恢复之间的任务交接，并把“打开完整会话”放到任务列表和详情首层。正式版仍为 0.0.18。

## 新功能

- OpenUI 交互结果作为可选预览，默认关闭。开启后，Desktop 可查看同一结果版本的表格、图表和筛选条件。继续讨论时沿用原结果和明确提交的条件。CLI 可用 `peer result` 读取固定结果的摘要。
- 受管清理仅开放给满足部署与停稳条件的 Linux x64/ext4 本机维护环境。普通使用通过原会话和资源区查看结果。

## 修复与改进

- 已确认的后台等待保留具体对象，不再被当成反复无进展；资源仍忙时由本地宿主等待，实际可用后再继续协调，避免用模型重复轮询。
- 停止当前回复会先保存停止状态。即使应用在请求收尾前退出，重开仍能看到继续入口。明确继续时沿用原任务和已完成结果。
- 接管与原生恢复共用当前停稳回执和准入判断；已有的未完成接管不会再被另一次恢复覆盖。符合严格身份和回执条件的旧交叉状态，经原停止屏障收尾后恢复原任务，保留历史和预算。
- 运行、人工请求、未确认停止和技术修复使用同源事实决定下一步；活跃执行或缺失会话事实不会被根目标关闭忽略。阅读和引用旧任务不会自行取得执行权。
- 任务列表可直接打开完整会话；任务详情的会话入口始终可见，核验、证据及其他资料由独立的“任务详情”按钮展开，保留任务来源和原会话身份。
- 补充主 Bot 的排查规则：区分观察与假设，核对运行版本和源码范围；搜索没有新增证据时重新检查范围，避免将零命中解释为代码不存在。
- TUI 首次绑定在同一屏集中展示选择与按键提示。点离输入框后可以直接打字，新发消息的时间显示在对话行右侧。
- 同步中英文发布说明、用户文档和站点更新日志。

## 升级与验证范围

- 延续联合协调格式 9。更新前保留完整数据备份；历史未知外部效果继续受到原范围保护，不会为解除等待而被清空。
- 更新不会自动重启已取消的个人任务。发布检查、隔离恢复用例与实际个人任务完成是不同的验收范围；本版不宣称真实模型质量或所有旧任务已恢复。

## Release notes

- **0.1.0-rc.36** repairs task handoffs across waiting, stopping and recovery, and keeps Open full conversation directly reachable in task lists and details. Stable remains 0.0.18.

## What's new

- OpenUI interactive results are an opt-in preview. Desktop displays tables, charts and filters on a fixed result version. Follow-ups can reference that result and the conditions you explicitly submit. The CLI can read its summary with `peer result`.
- Managed cleanup is available in Linux x64/ext4 maintenance environments that meet the deployment and shutdown requirements. Everyday access uses the original conversation and workspace.

## Fixes and improvements

- Preserve admitted background waits and their targets without treating them as repeated lack of progress. The local host waits for busy resources and resumes coordination when they are available, without repeated model polling.
- Stopping a reply records the stop before the request finishes winding down. The Continue action is restored if the app exits during that interval. Continuing uses the original work and its completed results.
- Takeover and native resume share the current stop proof and admission checks. Another resume cannot overwrite unfinished takeover custody. Strictly matching retained interleavings settle through the existing stop barrier before the original task resumes with its history and budget.
- Use shared facts to distinguish execution, human requests, unconfirmed stops and technical repair. Root closure cannot ignore live execution or missing owned-session facts. Reading or citing an old task does not create execution authority.
- Open complete conversations directly from the task list or the visible detail action row. A separate Task details button discloses verification, evidence and secondary information while preserving the original task and conversation identities.
- Add investigation rules for the main Bot: separate observations from hypotheses, compare runtime and source revisions, and revisit search scope when repeated queries add no evidence. Zero matches do not establish that code is absent.
- TUI shows the first-run binding choices and keys together. Typing after clicking away returns focus to the composer. Newly sent messages show their time at the right edge.
- Update bilingual release notes, user documentation and the website changelog.

## Upgrade and validation scope

- Retain combined coordination format 9 and a complete pre-update backup. Unknown historical external effects keep their existing protection; recovery does not erase them to unblock a directory.
- Updating does not automatically restart cancelled personal tasks. Release checks, isolated recovery scenarios and actual personal-task completion have different acceptance scopes. This release does not establish real-model quality or recovery of every old task.
