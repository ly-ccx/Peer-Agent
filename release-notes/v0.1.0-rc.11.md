## 发布状态

- **0.1.0-rc.11** 汇总任务取消、回复恢复、独立 Agent 通信和本地看图修复，供继续评测。正式版仍为 0.0.18；全面验收、连续七天日用与正式版批准仍按原计划执行。

## 任务与回复

- 等待跟进的任务可以直接在主对话或任务详情中取消。提交期间阻止重复点击；失败保留任务并可重试，成功后显示最新取消状态，历史结果与其他工作保留。
- “查看详情”对齐当前消息气泡的右边缘，悬停或键盘聚焦时出现。进度文字根据真实活动说明正在阅读、查看或整理什么，不再只有固定的“正在回复”。
- 连接中断或回复未完成时，从已保存的检查点接着推进，保留已执行工具和公开进展。缺少检查点、等待调度、次数耗尽和登录问题分别说明，不将旧工作重新执行一遍。

## 独立 Agent 与本地图片

- 子 Agent 使用独立工作会话执行任务，与主 Bot 双向通信。主对话呈现具名 Agent 的真实开始、运行、等待和完成动态，技术过程按需查看；向主 Bot 提问与等待用户决定分开表达。
- 协调消息、答复归属和任务接手结果在本地保存，恢复期间到达的新消息不会丢失；取消、暂停和用户授权继续由本地宿主决定。
- 主 Bot、执行 Agent 与只读核验 Agent 共用本地看图入口，支持 PNG、JPEG、GIF 和 WebP。已授权图片以真实像素送入支持视觉的模型；普通文本读取会提示使用看图工具，不再输出图片乱码。
- 图片读取受路径授权、文件类型、大小和像素边界约束。证据与检查点保存来源和重读线索，图片像素只保留在当前回合；恢复后重新读取图片。
- 同步中英文发布说明、用户指南和站点更新日志。

## 升级与回退

- RC4–RC10 可在“设置 → 更新与关于”通过自动或 Beta 通道检查 RC11；旧 Beta5/RC1–RC3 请下载匹配架构的安装包手动升级。
- 退出旧宿主，备份完整数据根，Desktop、CLI/TUI 与 Gateway 同步升级。npm 固定版本为 `@peer-agent/cli@0.1.0-rc.11`，`@rc` 跟随后续候选；归档中的 peer 与凭据助手须保持同目录。
- 回退时恢复升级前的完整备份，并另存新数据与产物。不要让旧版本直接写入新版使用过的数据目录，无需为升级重置数据。

## 验证与已知限制

- 源码界面与图片链路由实施者自审，非独立审查；受控模型用于复现通信、恢复和图片投递，不证明真实模型的回复质量或网络时序。本地图片修复尚未实连云端模型验收。
- 原历史统计任务仍需受治理的历史查询能力和实际证据；新增看图或恢复能力不代表原任务已经完成，也不会自动签收旧任务。
- 发布检查覆盖三平台桌面资产、两平台 CLI、更新清单和 macOS 签名公证。Windows/Linux 交互安装、完整读屏、复杂写任务 Evidence 完整性、跨供应商独立复核和长期日用仍需对应验收；总体 Ready 与 GA 未宣告通过。

## Release status

- **0.1.0-rc.11** integrates task cancellation, reply recovery, independent Agent communication and local-image fixes for continued evaluation. Stable remains 0.0.18; comprehensive acceptance, seven days of daily use and stable-release approval remain required.

## Tasks and replies

- Cancel follow-up tasks directly from the main conversation or task details. Pending submissions prevent duplicates; failures retain the task for retry. Successful cancellation uses the latest host state and preserves history and unrelated work.
- Details follows the right edge of the current message bubble and appears on hover or keyboard focus. Progress describes actual reading, inspection or reply preparation rather than one fixed replying label.
- After an interruption or unfinished reply, resume from the saved checkpoint with executed tools and public progress retained. Missing checkpoints, scheduling, exhausted attempts and authentication receive distinct explanations without restarting previous work.

## Independent Agents and local images

- Child Agents execute in independent work conversations and communicate with the main Bot in both directions. Named, factual start, running, waiting and completion activity appears in the main conversation, with process details available on demand. Asking the parent Bot and waiting for a human decision remain distinct.
- Coordination messages, answer ownership and handoff results persist locally, including messages arriving during recovery. Cancellation, pausing and authorization remain under local host control.
- The main Bot, workers and read-only verifiers share a local image entry for PNG, JPEG, GIF and WebP. Authorized pixels reach vision-capable models; text reads redirect to the image tool instead of returning binary text.
- Image reads enforce path authorization, format, byte and pixel limits. Evidence and checkpoints retain source references and re-read hints; pixels remain current-turn context and are read again after recovery.
- Refresh bilingual release notes, user guidance and the website changelog.

## Upgrade and rollback

- RC4–RC10 can check for RC11 through Auto or Beta in Settings → Update & About. Older Beta5/RC1–RC3 require a manual installer matching their architecture.
- Quit older hosts, back up the complete data root and upgrade Desktop, CLI/TUI and Gateway together. Use `@peer-agent/cli@0.1.0-rc.11` for a fixed npm version; `@rc` follows later candidates. Keep peer and its credential helper together.
- Roll back with the complete pre-upgrade backup while retaining new data and artifacts separately. Do not let an older version write to a directory already used by the new version. Upgrading does not require a reset.

## Validation and known limits

- The implementer reviews source UI and image delivery, not an independent reviewer. Scripted cognition reproduces communication, recovery and image transport rather than live model quality or network timing. Local-image delivery has not yet been validated against a live cloud model.
- The earlier history-statistics task still requires governed history access and actual evidence. Image and recovery fixes do not establish its completion or automatically accept old tasks.
- Release checks cover three desktop platforms, two CLI platforms, update manifests and macOS signing and notarization. Interactive Windows/Linux installation, full screen-reader coverage, complex-write Evidence, independent cross-provider review and long-term use still require their corresponding acceptance. Overall readiness and GA are not declared complete.
