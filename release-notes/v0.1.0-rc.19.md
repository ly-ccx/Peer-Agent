## 发布状态

- **0.1.0-rc.19** 修复长回复被错误判为失败、有效复核总结被拦截，以及大历史项目执行时输入和滚动卡顿的几条关键路径。正式版仍为 0.0.18。

## 修复与优化

- 兼容流收到协议结束标记后立即交出回复和工具调用；取消、超时不再等待底层连接关闭，调用方取消信号持续覆盖整个响应体。
- 新用户输入可抢占没有活跃工具派发的后台模型请求，保留原工作检查点与事件归属；已派发或未知操作仍按原结果路径收尾。

- 主 Bot 从本地完整执行回执判断 post_reply 和等待结果，界面工具预览仍保持有界。长回复不会因为预览裁剪而丢失成功标记、正式消息和宿主来源版本。
- 已有真实工具结果的复核总结不再因出现“工具返回”、exitCode 或“我检查了”而误报伪工具协议。真正的伪调用标签、未执行行动旁白仍拦截；证据和正式签收门禁保留。
- 切换模型或连接后，对已完成且没有未知副作用的主回复，使用当前模型依据已有结果继续认知；不跨模型回放原生调用，不重放旧工具，不清空用量。未决执行继续明确阻塞。
- 历史错误折叠后仍可按原始消息身份打开详情，保留该次过程和原始错误；修复虚拟列表短暂卸载后引用反馈丢失。
- 计划发现只解析相关委派计划；一次只读查询共享事实快照；没有待恢复工作的机器人不再反复扫描整份任务名册。
- 主对话摘要与恢复卡读取使用版本校验的有界投影，追加消息无需重复读取整份历史；并发写入导致版本变化时有限重试，不返回过期事实。
- 合并流式通知、保留未变消息引用，减小虚拟列表窗口，并移除执行状态的持续背景重绘，降低运行时对输入和滚动的影响。

## 升级与验收范围

- 升级前备份完整数据根；Desktop、CLI/TUI 与 Gateway 同步升级。延续 RC18 协调日志兼容性约束，回退须恢复完整升级前备份。
- 大历史验收使用与现场规模相当的合成历史；用户真实历史只读用于本地定位，不发送到云模型。真实任务与受控 UI 回归分别记录。
- 截图为实施者自审，不称独立产品审查；任务复核使用独立上下文，可能仍为同源模型。Windows/Linux 交互安装、完整读屏、安装器交接及长期日用不在本轮断言内。

## Release status

- **0.1.0-rc.19** repairs failed delivery of long replies, false rejection of valid verifier summaries, and key input/scroll bottlenecks during execution with large project histories. Stable remains 0.0.18.

## Fixes and improvements

- Settle compatible streams at protocol completion and release cancellation or timeout without waiting for transport cleanup. Caller cancellation remains active throughout the response body.
- Admit fresh user input ahead of background model requests with no active tool dispatch, preserving the original work checkpoint and event ownership. Dispatched or unknown operations retain their existing result handling.

- Use complete local execution receipts for post_reply and structured waits while keeping UI previews bounded. Preview clipping no longer removes success, canonical replies or host source revisions.
- Permit factual summaries after actual tool results without rejecting words such as exitCode or “I verified”. Literal pseudo calls and unexecuted action preambles remain blocked; Evidence and host acceptance remain required.
- After changing model or connection, safely continue reasoning over completed results with the current model. Never replay another model's native calls, repeat completed tools or reset usage. Unknown execution outcomes remain blocked.
- Resolve folded historical error details by canonical message identity, retaining the original process and error. Preserve reference feedback across temporary virtual-row unmounts.
- Parse only delegated plan candidates, share facts within one read query, and avoid full recovery-roster scans for bots with no eligible work.
- Use bounded, version-checked history and recovery projections. Metadata-only append receipts avoid rereading full history; concurrent version changes receive bounded retries without stale fallback.
- Coalesce streaming notifications, retain unchanged message identities, reduce the virtual window and remove continuous status-background repainting to improve interaction during execution.

## Upgrade and validation scope

- Back up the complete data root and upgrade Desktop, CLI/TUI and Gateway together. RC18 coordination-journal compatibility restrictions still apply; rollback requires the complete pre-upgrade backup.
- Large-history acceptance uses synthetic history matching the observed scale. Personal history is read locally for diagnosis and is not sent to cloud models. Real-model tasks and controlled UI regression are recorded separately.
- Screenshots are implementer self-review, not independent product review. Task verification uses a separate context and may share the same model lineage. Interactive Windows/Linux installation, full screen-reader coverage, installer handoff and long-term use remain outside this claim.
