# 48. 渠道无关的模型选项与渠道投影

创建时间：2026-07-17
最后更新：2026-07-17

## 状态

Accepted，先以 Qoder 上下文档位完成端到端实现。

## 背景

不同模型渠道除了模型标识、上下文窗口、输出上限、视觉和推理能力等共同元数据，还会暴露仅由该渠道定义的可选配置。例如 Qoder 为部分模型声明 `200K / 400K / 1M` 上下文档位：默认档位的总上下文是 200K，而目录中的 `max_input_tokens` 是扣除输出等预留后的 180K 输入预算。

若把这些配置直接写成 Qoder 专用字段并散落在存储、界面和聊天运行时中，后续每接入一个渠道都会增加条件分支；若把渠道原始 JSON 直接透传给界面和请求层，又会让通用层依赖上游私有格式，无法稳定迁移、校验和持久化。

因此需要区分稳定的通用模型配置契约与可替换的渠道适配器：通用层只理解声明式选项及其已选值，渠道层负责把原始目录归一化，并把选择投影回该渠道的请求参数和本地上下文预算。

## 决策

### 决策一：通用层拥有稳定模型元数据与声明式选项

模型目录继续用稳定字段表达跨渠道都具有明确语义的元数据：模型标识与名称、上下文窗口、输出上限、能力标记和定价。渠道可另外声明一组可序列化的有限单选配置：

```ts
interface LlmModelOptionDefinition {
  id: string;
  label: string;
  kind: 'select';
  choices: Array<{
    value: string;
    label: string;
    description?: string;
  }>;
  defaultValue?: string;
}

type LlmModelOptionValues = Record<string, string>;
```

选项定义只描述渲染和校验所需信息，不包含函数、渠道密钥、请求字段路径或渠道原始 JSON。选项 ID 和 choice value 必须在同一模型内稳定，才能安全持久化和迁移。

### 决策二：渠道适配器拥有归一化与请求投影

每个渠道在自己的适配器边界内完成两项工作：

1. **目录归一化**：把渠道原始模型元数据转换为通用模型元数据和声明式选项；
2. **请求投影**：把已验证的选项值转换成该渠道实际需要的请求参数，并给出运行时可使用的有效上下文预算。

通用 UI 不识别 `context_config`、Qoder 档位名称或未来渠道的私有字段；聊天主机不通过不断增加 `channelId` 分支解释选项。请求字段、默认行为和预算换算留在 Provider Adapter seam 内。

未知选项、未知 choice、过期目录值和缺失选项均不得原样注入请求。适配器必须回退到当前目录声明的默认值；目录没有默认值时，不投影该选项并保留现有请求行为。

### 决策三：已选值属于模型实例配置

选项定义来自模型目录，是可刷新的能力描述；用户选择属于 provider 组下的模型实例配置，与模型级的上下文、推理和能力字段一起持久化。

- 存储只保存经过定义校验的 `optionValues`，不复制整份目录定义。
- 读取旧配置时，缺少 `optionValues` 等价于使用当前目录默认值。
- 目录刷新后，仍存在且合法的选择继续保留；已移除或非法值回退默认值。
- 多个 provider 组即使选择同一模型，也分别保存各自的选项值。
- 凭证、OAuth token 和本地 CLI 鉴权信息不进入模型选项。

### 决策四：Renderer 只做通用表达

Renderer 根据声明式定义渲染通用控件，并通过现有 provider/model 配置 IPC 提交选项值。Renderer 不直接读取渠道缓存、不解释渠道请求协议，也不保存权限或鉴权事实。

首期只实现 `select`，后续若多个渠道出现稳定且共同的需求，可在协议中增加 `boolean`、数值范围等新 kind。不得为了单一渠道把任意 JSON Schema、动态脚本或渠道组件注册进通用协议。

### 决策五：Qoder 上下文档位是首个适配案例

Qoder 适配器把 `context_config` 归一化成 ID 为 `contextTier` 的 select 选项：

- choice value 使用 Qoder 目录中的稳定档位键，如 `200K`、`400K`、`1M`；
- `is_default` 决定默认选择；
- `token_count` 用于展示总上下文窗口并计算运行时预算；
- 默认 200K 档位保留目录给出的 180K 最大输入预算；
- 扩展档位的请求字段和有效输入预算由 Qoder 请求适配器集中投影，不由 UI 猜测。

模型卡应区分“总上下文档位”与“最大输入预算”，不能再把 180K 输入预算单独标成模型的最高上下文能力。

## 模块边界

```text
渠道目录 / 本地缓存
  -> Provider Model Catalog Adapter
    -> 通用 Model Metadata + Option Definitions
      -> Provider/Model Config Store 保存 Option Values
        -> 通用 Renderer 控件
          -> Provider Request Adapter 投影请求与预算
```

- Protocol：定义可序列化选项、已选值和跨进程错误语义。
- Catalog Adapter：归一化渠道目录、选择默认值。
- Config Store：迁移、校验和持久化模型实例选择。
- Renderer：声明式展示与交互，不含渠道条件分支。
- Request Adapter：生成渠道请求参数和有效上下文预算。
- Evidence/Tool Runtime：不因模型选项增加新的执行路径；现有本地能力治理链保持不变。

## 兼容与失败语义

1. 旧配置无需迁移脚本即可读取，缺失选项使用目录默认值。
2. 渠道目录不可用时继续使用渠道已有 fallback 模型；fallback 可声明最小选项或不声明选项。
3. 非法选项值在存储入口和请求投影入口均需防御，不能穿透到渠道请求。
4. 某个渠道不声明选项时，界面和请求行为与当前版本一致。
5. 模型目录更新不得覆盖用户仍然合法的已选值。

## 验证要求

1. 协议类型和解析测试覆盖合法定义、重复 ID、非法默认值和未知 choice。
2. 存储测试覆盖选择保存、重启恢复、旧配置读取及目录变化后的回退。
3. Qoder 目录测试覆盖 200K、400K、1M 归一化及默认档位。
4. Qoder 请求测试证明选择会投影到请求，并同步改变运行时上下文预算。
5. Renderer 测试证明通用 select 能展示和更新任意渠道声明的选项，不依赖 Qoder 字段。
6. 不声明模型选项的现有渠道、模型选择和请求测试保持通过。

## 不做的事情

- 不允许渠道原始配置对象直接跨 IPC 进入 Renderer。
- 不构建可执行脚本、任意 JSON Schema 或渠道自定义 React 组件系统。
- 不把模型选项与 API Key、OAuth、CLI 登录或工具权限混为一体。
- 不把 1M 总上下文简单等同于 1M 最大输入；预算必须由渠道适配器给出。
